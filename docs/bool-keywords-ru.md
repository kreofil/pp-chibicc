# Булевы ключевые слова bool, true и false

ppchibicc распознаёт `bool`, `true` и `false` без подключения `<stdbool.h>`:

```c
bool enabled = true;

bool negate(bool value) {
  return !value;
}
```

`bool` обозначает тот же тип, что `_Bool`. Константы `true` и `false` имеют
тип `bool` и значения 1 и 0, как в C23. На текущей Linux x86-64 платформе
размер и выравнивание типа равны одному байту. Поддерживаются переменные,
массивы, поля структур, обычные параметры/результаты и обработчики 4П.
Соглашение вызовов и раскладка совпадают с существующим `_Bool`.

## Типы и преобразования

```c
enum {
  LiteralIsBool = _Generic(true, bool: 1, default: 0), // 1
  LiteralBytes = sizeof(true),                       // 1
  Sum = true + true                                 // 2, после продвижения в int
};

bool a = 256;   // true
bool b = 0;     // false
bool c = -0.0;  // false
```

Преобразование скаляра в `bool` даёт 0 или 1. Ненулевые целые числа,
ненулевые указатели и NaN дают `true`; целочисленный ноль, нулевой указатель
и оба знаковых вещественных нуля дают `false`.

Операции `+`, `~` и передача среди `...` применяют целочисленные продвижения:
`true + true` равно 2, `~true` равно -2, а неименованный булев аргумент
читается через `va_arg(ap, int)`. Результат `!value` имеет тип `int`, как в C.

Инициализаторы со статическим временем хранения также нормализуются до 0/1.
Исправлены унаследованные случаи `_Bool`: значение `512` больше не обрезается
до нулевого байта; преобразование адреса в bool не создаёт указательную
релокацию в однобайтовом поле. Native-преобразование NaN в bool теперь даёт
`true`, включая вычисление констант самокомпилированным stage2.

## Заголовок и препроцессор

`#include <stdbool.h>` остаётся допустимым. В ppchibicc этот заголовок
сохраняет ключевые слова и не заменяет их старыми макросами `true` → `1`
и `false` → `0` типа `int`. Маркер `__bool_true_false_are_defined` сохраняется.

```c
#if true && !false
// Ветка включена и без stdbool.h.
#endif
```

`defined(true)`, `defined(false)` и `defined(bool)` проверяют наличие
макросов, а не ключевых слов; без пользовательских определений результат
равен 0. `#undef` этих имён не отключает ключевые слова. Макросы раскрываются
до вычисления `#if`/`#elif`, включая появившиеся после раскрытия `true`/`false`.

Для сторонних C-компиляторов в режимах C11/C17 наш `<stdbool.h>` сохраняет
традиционные макросы; в их режиме C23 используются ключевые слова.

Ключевые слова доступны в режиме ppchibicc по умолчанию. Это выборочная
поддержка C23, как и `nullptr`, а не объявление полной реализации стандарта.
`__STDC_VERSION__` сохраняет прежнее значение `201112L`. Имена `bool`, `true`
и `false` зарезервированы как ключевые слова.

## Пример 4П

[Пример флагов](../examples/llvm/ppc-bool-flags.c) хранит `bool` в поле
обобщения и использует bool в обычном параметре и результате функции 4П.
Специализация полиморфного аргумента выбирает обычную или инвертированную
проверку:

```sh
bin/ppchibicc --backend=llvm -O2 examples/llvm/ppc-bool-flags.c -o build/ppc-bool-flags
build/ppc-bool-flags
```

Ожидается `regular=1, inverted=0`. Поддерживаются native, LLVM и закрытая
сборка; условия оптимизации таблиц полиморфных функций сохраняются.

## Проверки

```sh
cmake --build build --target test-all test-llvm test-llvm-stage2
cmake --build build --target test-llvm-closed-compiler test-llvm-closed-compiler-stage2
```

`test/bool-keywords.c` проверяет использование до/после заголовка, типы,
размеры, константные выражения, препроцессор, массивы/VLA, инициализацию,
преобразования, NaN, `switch`, указатели на функции и вариадические продвижения.
Отдельный host-модуль проверяет вызовы в обе стороны, стековые аргументы
и структуры с булевыми полями, используя `_Bool` в режиме C11.

`test/ppc-bool.c` и `cmake/run-bool-keyword-tests.sh` проверяют обработчики,
мультиметоды, агрегатные результаты и `stdarg` во всех режимах диспетчеризации,
а также 11 недопустимых использований ключевых слов. Проверяются stage1/stage2,
LLVM O0/O2, закрытая сборка и заголовок у сторонних C11/C17/C23 компиляторов.
