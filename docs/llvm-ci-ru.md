# CI с LLVM

Workflow `.github/workflows/test.yml` запускается при push и pull request.
Он содержит две независимые проверки на Ubuntu 24.04:

| Job | Проверки |
| --- | --- |
| `cmake-test-all` | Обычный `test-all`: native stage1, самокомпиляция stage2, тесты C/4П и примеры |
| `llvm-23` | `test-llvm`, `test-llvm-stage2`, `llvm-opt-demo`, `llvm-dispatch-demo`, `llvm-dispatch-report`, `test-llvm-dispatch-report-stage2`, `llvm-static-dispatch-demo`, `test-llvm-static-dispatch-stage2`, `test-llvm-static-dispatch-bench`, `test-llvm-static-dispatch-bench-stage2` |

LLVM-набор проверяет IR, выполнение при O0/O2, ABI с системным GCC,
смешанные native/LLVM-объекты, регистрацию 4П, команды компилятора и
диагностики. В него входят скалярный `stdarg` и совместимость `va_list`,
`.ppc`/`.pph`, пустые списки `()`, switch и
восемь этапов эволюционного примера фигур с эталонами.
Сам stage2 пока собирается исходным x86-64 backend, после чего тестируется
его LLVM-генератор. Полная самокомпиляция через LLVM остаётся отдельной задачей.

## Инструменты

Обе job используют Python 3.12 и CMake 3.31.6. CMake устанавливается из PyPI;
GCC, Make, системные заголовки и библиотеки берутся из образа Ubuntu runner.
Их версии выводятся в лог.

В `cmake/ci-llvm23.json` закреплены версия 23.1.6, точные URL и SHA256 четырёх
пакетов из официального репозитория `apt.llvm.org` для Ubuntu Noble amd64.
`cmake/setup-ci-llvm.py` проверяет контрольные суммы и распаковывает пакеты
через `dpkg-deb` в пользовательский каталог. Обёртки для `llvm-as`, `opt`,
`llc` и `llvm-link` выбирают библиотеку LLVM из этого же каталога; проверяется
точное совпадение версий инструментов.

Установка LLVM не требует `sudo` и изменения системных APT-репозиториев.
Таким образом, подготовка инструментов не зависит от зеркала
`azure.archive.ubuntu.com`, на разрешении имени которого останавливался
прежний шаг `apt-get`. Сетевой доступ к PyPI и официальному репозиторию LLVM
нужен при первом получении пакетов.

Actions cache хранит только сжатые LLVM-пакеты, с ключом по содержимому
lock-файла. При повторном запуске SHA256 снова проверяются и инструменты
распаковываются заново. Обновление сборки LLVM выполняется согласованным
изменением URL, версии и хешей в lock-файле.

В эти же цели входят проверки `long double`: точность констант, IEEE,
ABI агрегатов, вариадические списки и обработчики 4П. Отдельные тестовые
модули собираются системным C-компилятором для проверки вызовов в обе стороны.

В LLVM-набор включены также режимы `runtime`/`table`/`switch` закрытой
диспетчеризации: проверяются неизменяемые массивы, прямые ветви и запасной
runtime-вызов при регистрации другого обработчика из native/LLVM-модуля.
Мультиметоды проверяются на матрицах `2×3` и `2×3×2`, с общим обработчиком
до/после конкретных, структурными и вариадическими результатами. Проверяются
все шесть порядков трёх объектов, включая непрозрачный модуль, и диагностика
неполной закрытой таблицы до `main`. Один открытый аргумент или слишком
большая матрица сохраняют runtime-путь. Native-набор отдельно проверяет
преобразование VLA в указатель среди вариадических аргументов мультиметода.

Метаданные и межмодульный отчёт проверяются stage1 и stage2: сбор всей
матрицы, пропуски и внешние объявления, частные обработчики и переименование
LLVM, открытые/непрозрачные аргументы, несовместимые описания типов/ABI,
bitcode/O2 и все шесть порядков модулей исполняемого примера.
Статические таблицы проверяются обоими компиляторами во всех режимах и
порядках модулей, включая структуры/varargs, соседние открытые семьи,
свёртку известного вызова и отказ при записи/утечке адреса таблицы,
неполных метаданных или неизвестной пользовательской зависимости.
Для бенчмарка CI собирает четыре варианта и проверяет 256 результатов
по независимому Python-эталону и неправильные аргументы. Оба компилятора
проверяются без калибровки и сбора статистики; порогов быстродействия нет.

## Повторение LLVM-проверок

С обычной установленной версией LLVM 23 достаточно команд из
[инструкции компилятора](llvm-compiler-ru.md). Для той же сборки инструментов,
что в CI, на совместимой Linux x86-64 системе можно использовать:

```sh
python3 cmake/setup-ci-llvm.py --prefix "$PWD/build-llvm-tools"
export PATH="$PWD/build-llvm-tools/bin:$PATH"

cmake -S . -B build-llvm-ci \
  -DCMAKE_C_COMPILER=gcc -DPPCHIBICC_LLVM_VERSION=23
cmake --build build-llvm-ci --target \
  test-llvm test-llvm-stage2 llvm-opt-demo llvm-dispatch-demo \
  llvm-dispatch-report test-llvm-dispatch-report-stage2 \
  llvm-static-dispatch-demo test-llvm-static-dispatch-stage2 \
  test-llvm-static-dispatch-bench test-llvm-static-dispatch-bench-stage2
```

Для установочного скрипта нужны Python 3.11+, `curl`, `dpkg-deb` и системные
библиотеки, совместимые с пакетами Ubuntu 24.04. Каталог сборки должен быть
новым либо содержать правильные пути инструментов в CMake cache.
`manifest.json` рядом с распакованными инструментами сохраняет рецепт
установки с URL и контрольными суммами.

При ошибке LLVM job сохраняет каталоги `build-llvm-ci/llvm-*` в артефакт
`llvm23-diagnostics-…` на семь дней: исходный/оптимизированный IR, сообщения
тестов, результаты выполнения и отчёты demo. Ошибки подготовки инструментов
видны в логе соответствующего шага.

PGO с compiler-rt и измерения производительности остаются отдельными
исследовательскими целями; обязательная job проверяет корректность генерации,
ABI и оптимизационных pipeline.
