# Вариадические функции и stdarg в LLVM

LLVM backend ppchibicc поддерживает определения функций с `...`, чтение
скалярных и агрегатных аргументов через `<stdarg.h>`, копирование и передачу `va_list`.
Это относится к обычным C-функциям и обработчикам 4П на Linux x86-64 / System V.

```c
#include <stdarg.h>
#include <stdio.h>

long sum(int count, ...) {
  va_list ap;
  va_start(ap, count);
  long result = 0;
  for (int i = 0; i < count; i++)
    result += va_arg(ap, int);
  va_end(ap);
  return result;
}

int main() {
  printf("sum=%ld\n", sum(4, 10, 20, 30, 40));
  return 0;
}
```

Для сохранённого `program.c`:

```sh
bin/ppchibicc --backend=llvm -O2 program.c -o program
./program
```

Ожидается `sum=100`. Допускаются прямые вызовы и указатели на вариадические
функции. Внешние `printf` и другие вариадические функции также поддерживаются.

## Типы и продвижения

Среди `...` передаются целые числа, указатели, вещественные значения,
структуры и объединения.
Как требует C, `_Bool`, `char` и `short` продвигаются к `int`, `float` —
к `double`. Поэтому переданное значение `float` читается через
`va_arg(ap, double)`, а узкое целое — через `va_arg(ap, int)`.
Тип чтения должен соответствовать фактически переданному продвинутому типу.
`long double` сохраняет свой тип: он передаётся в выровненной стековой области
и читается через `va_arg(ap, long double)`. Именованные параметры этого типа
также поддерживаются; примеры и ABI — в [отдельном руководстве](llvm-long-double-ru.md).

Учитываются исчерпание шести GP/восьми SSE-регистров, чередование классов
и переход на стек. Именованные параметры могут включать структуры по
значению; понижение LLVM учитывает их классы и передачу через память.
Возвращать можно также малые и крупные структуры: скрытый указатель `sret`
входит в расчёт позиции неименованных аргументов.

`va_arg` проверяет совместимость первого аргумента с `va_list` и требует
полный объектный тип результата. Структуры и объединения читаются с учётом
INTEGER/SSE-регистров и стека; подробности и ограничения совместимости — в
[руководстве по агрегатным аргументам](llvm-vararg-records-ru.md).
Атомарные и `volatile`-типы по-прежнему диагностируются LLVM-бэкендом.
Агрегатные вызовы без прототипа остаются неподдерживаемыми.

## Копирование и передача списка

`va_copy` создаёт независимые курсоры: чтение копии не меняет позицию
оригинала. Повторный `va_start` начинает чтение заново в той же функции.
Для каждого пользовательского списка используйте `va_end` по правилам C.

`va_list` можно передать функции-потребителю, например `vsnprintf`,
либо в другой модуль, собранный GCC/Clang. Функция, получающая `va_list`
как параметр, может читать его через тот же `va_arg`; при этом передача
списка в System V использует указатель на его состояние.

## Параметры 4П

Пример сигнатуры: `double Total<Value *v>(int count, ...)`. Обработчик
специализации задаётся как `double Total<Value.number *v>(int count, ...)`.
Обе функции используют `va_start(ap, count)` и обычные средства `stdarg`.
Вызов имеет вид `Total<pointer>(3, 1.25, 2.5, 3.75)`.

Указатели полиморфных параметров из `<...>` учитываются как именованные параметры
реальной ABI-сигнатуры. Поддерживаются мультиметоды, строгие enum-обобщения
и возврат крупных структур из вариадического обработчика.
Теги, таблицы регистрации и правила выбора обработчиков сохраняются.

## Представление System V

Общее представление `va_list` содержит четыре поля: `gp_offset`, `fp_offset`,
`overflow_arg_area`, `reg_save_area`. Размер состояния — 24 байта.

| Область сохранённых регистров | Слотов | Размер слота | Смещения |
| --- | ---: | ---: | --- |
| GP | 6 | 8 байт | 0–47 |
| SSE | 8 | 16 байт | 48–175 |

`overflow_arg_area` начинается после именованных аргументов, переданных
на стеке. При исчерпании нужного класса регистров чтение продолжается там.

На входе LLVM-функции `llvm.va_start` инициализирует исходное состояние.
Макрос `va_start` копирует его в пользовательский список. На каждом обычном
возврате и при достижении конца функции вызывается `llvm.va_end`.
Именованные аргументы и регистровую область сохраняет backend LLVM.
Доступ к отдельному аргументу представлен типизированным `ND_VA_ARG`;
для скаляров он понижается через общие функции заголовка. Для агрегатов
бэкенд проверяет доступность обоих классов регистров и собирает значение
из сохранённых слотов либо копирует его со стека в отдельный временный объект.

Native backend отдельно резервирует 176 байт для регистров и создаёт то же
24-байтовое состояние, учитывая классы именованных параметров и их стековую
часть. `va_copy` копирует состояние, сохраняя общий указатель на регистровую
область. На этой платформе пользовательский `va_end` не освобождает ресурсов.

**Совместимость старых объектов:** прежняя native-реализация использовала
частную раскладку SSE со слотом 8 байт. Native-объекты и библиотеки, которые
создают, читают или передают `va_list`, нужно пересобрать начисто вместе с
обновлённым `stdarg.h`. Новая раскладка совместима с System V GCC/Clang.

## Проверки

```sh
cmake -S . -B build-llvm23 -DPPCHIBICC_LLVM_VERSION=23
cmake --build build-llvm23 --clean-first --target test-all test-llvm test-llvm-stage2
```

`test/stdarg-abi.c` и `test/ppc-varargs.c` входят в native stage1/stage2
и LLVM-набор. Для обычного C независимым эталоном служит системный компилятор;
отдельный host-модуль проверяет вызовы в обе стороны и передаёт свой `va_list`
в функции ppchibicc. Межмодульный пример 4П дополнительно смешивает
native/LLVM-определения вариадических обработчиков.

`test/stdarg-records.c`, `test/ppc-vararg-records.c` и отдельный host-модуль
проверяют агрегаты: классы INTEGER/SSE, нехватку регистров, стековое
выравнивание 16/32 байта, packed- и X87-объекты, `va_copy`, передачу списка
между модулями и повторное использование временных буферов в циклах.

Проверены GP/SSE и стековые границы, именованные стековые параметры,
структуры в именованной части, `sret`, независимые копии и перезапуск,
однократное вычисление выражения списка, указатели, узкие продвижения,
знаковый ноль и payload NaN, `vsnprintf`, мультиметоды и строгое обобщение.
Ошибки типов `va_arg` и ограничения LLVM покрыты диагностическими проверками.

Проверено на LLVM 19.1.7, 21.1.8 и 23.1.6 при O0/O2; stage2 — на LLVM 23.
Обязательные [CI-проверки](llvm-ci-ru.md) выполняют LLVM-набор на версии 23.
