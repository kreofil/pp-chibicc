# Безаргументные сигнатуры C и 4П

Для отсутствующего списка обычных параметров ppchibicc уже поддерживает
прототип `(void)`. Этот шаг согласует с ним объявления, определения и
обработчики в восьми CMake-проектах, остановившихся при предыдущем LLVM-аудите.
Изменены 34 сигнатуры в 19 исходных и заголовочных файлах.

## Запись сигнатуры и вызова

Обычная функция записывается как `int main(void)`. Для 4П процедурные
параметры остаются в отдельном списке `<...>`:

```c
double FigurePerimeter<Figure *f>(void);
double FigurePerimeter<Figure.rect *f>(void) {
  return RectanglePerimeter(&f->rect);
}

// Вызов в теле функции:
// double perimeter = FigurePerimeter<figure>();
```

`(void)` означает отсутствие **обычных** параметров. Объект `figure`
передаётся через список параметров 4П, как прежде. `void` указывается
в объявлениях и определениях, а при вызове скобки остаются пустыми.
Это относится и к обобщающей функции, и ко всем её обработчикам, и к
объявлениям в других единицах трансляции.

В модели C11/C17 объявление `f()` оставляет типы обычных параметров
неуказанными. Компилятор сохраняет прежнюю трактовку такой записи;
LLVM backend по-прежнему диагностирует определения без прототипов
и настоящие вариадические определения. Внешние вариадические вызовы
вроде `printf` сохраняют свою поддержку.

Семантика диспетчеризации 4П, расположение тегов, таблицы обработчиков
и регистрация сохраняются. Изменения исходников согласуют фиксированные
прототипы; расширения ABI и изменений генератора LLVM здесь нет.

## Проверки

```sh
cmake -S . -B build-llvm23 -DPPCHIBICC_LLVM_VERSION=23
cmake --build build-llvm23 --target test-all test-llvm test-llvm-stage2
```

Проверено с LLVM/Clang 23.1.6. `test-all` сохраняет native-проверки и
самокомпиляцию. `test-llvm` и `test-llvm-stage2` теперь также запускают все
восемь этапов `evolution/figures/evo-reuse-code` при O0/O2 и сравнивают
полученные файлы с эталонами. Это проверяет раздельную компиляцию объявлений,
обобщающих функций и обработчиков, включая повторное использование
`FigurePerimeter` на этапах 03 и 08.

Общий `cmake/run-example-tests.sh` принимает дополнительные аргументы
компилятора после первых двух параметров; списки файлов и эталоны одинаковы
для native- и LLVM-прогонов.

Дополнительно native- и LLVM O0/O2-программы дали одинаковые результаты:
пример потоков получил периметры 16, 22 и 28; adapter совпал со своим
эталоном; модули карт плоскости и тора проверены отдельным конечным запуском
`DrawMap` и `LivingCells` на сетке 3 × 3. Интерактивный цикл игр не запускался.

Повторить аудит CMake-проектов можно отдельно:

```sh
python3 cmake/audit-llvm-examples.py --compiler "$PWD/bin/ppchibicc" \
  --output build-llvm-example-audit-void
cat build-llvm-example-audit-void/report.md
```

`opt` и `llc` выбираются через `PATH` либо экспортированные
`PPCHIBICC_LLVM_OPT`/`PPCHIBICC_LLVM_LLC`. Результат от 2026-11-11:

| Результат | До согласования | После |
| --- | ---: | ---: |
| Успешная LLVM O2 сборка CMake-проекта | 15 | 23 |
| Совпавший выходной эталон фигур в аудите | 12 | 15 |
| Ошибка LLVM на пустых списках параметров | 8 | 0 |
| Ошибка CMake-настроек при обоих backend | 15 | 15 |

Все восемь прежних ошибок сигнатур устранены. Числа относятся к 38 полным
CMake-проектам; успешная сборка игры не означает проверку её интерактивного
цикла. Оставшиеся 15 проектов требуют согласовать `LANGUAGE C`, `-x c`
для `.ppc` и исключение заголовков `.pph`/`.h` из отдельной компиляции,
как описано в [инструкции компилятора](llvm-compiler-ru.md#файлы-ppc-и-pph).
