# Варианты продолжения работы над ppchibicc

План для ветки `feature/llvm-ir-mvp`, после завершения VLA и добавления
булевых ключевых слов.
Работа представлена в [PR №5](https://github.com/kreofil/pp-chibicc/pull/5).
Следующий этап выберем отдельно, с учётом новой практической задачи на PPC.

## Завершённый этап

`bool`, `true` и `false` доступны без заголовка с семантикой типов C23.
`bool` совпадает с `_Bool`; проверены препроцессор, инициализация, ABI,
обработчики 4П и закрытая сборка. Подробности — в
[руководстве по bool](bool-keywords-ru.md).

Поддерживаются локальные VLA, `alloca` и VLA в параметрах обычных и обобщённых
функций. Размеры могут ссылаться на предыдущие обычные параметры и поля
полиморфных параметров; определения сохраняют размеры при входе, прототипы
их не выполняют. Проверены native, LLVM O0/O2, stage2, закрытая сборка,
LLVM 19/21/23 и взаимные вызовы с GCC/Clang.

Текущее ограничение времени жизни: динамический стек освобождается при
возврате из функции; восстановление на выходе из блока VLA не генерируется.
Подробности и примеры — в [руководстве по VLA](llvm-vla-ru.md).

В документации приняты названия «полиморфные параметры» для списка `<...>`
в объявлении и «полиморфные аргументы» при вызове. Название парадигмы
«процедурно-параметрическое программирование» сохраняется.

## Варианты развития компилятора

1. **Битовые поля в LLVM.** Чтение и запись, знаковость, сохранение соседних
   полей, размещение и выравнивание структур. Проверить передачу таких
   структур по значению и совместимость с GCC/Clang.
2. **Агрегаты в вариадических вызовах.** Передача структур и объединений
   среди `...`, получение через `va_arg`, размещение в регистрах и на стеке,
   `va_copy` и совместимость с системным ABI. Скалярная часть уже работает.
3. **Пробная самокомпиляция через LLVM.** В отдельном каталоге собрать
   ppchibicc его LLVM-компилятором, проверить полученный компилятор и
   определить реальные оставшиеся препятствия. Состав необходимых доработок
   уточняется по результатам этой проверки.

Это варианты для выбора следующего этапа, без установленного срока.

## Совместная практическая задача на PPC

Пользователь планирует подобрать новую задачу для совместной реализации.
После её выбора:

- согласовать входные данные, ожидаемый результат и проверочные примеры;
- спроектировать обобщения, специализации и обработчики с применением 4П;
- реализовать небольшой работающий вариант и проверить корректность;
- сравнить native и LLVM, а при подходящем составе программы — закрытую
  LLVM-сборку; исследовать оптимизации после получения проверенного результата.

Такая задача может определить приоритет доработок компилятора.

## Сохраняемые границы проекта

Оптимизации закрытой диспетчеризации применяются, когда закрыты типы всех
полиморфных параметров и известен необходимый набор обработчиков. Открытые
обобщения сохраняют runtime-диспетчеризацию.

Отдельная утилита преобразования исходников, собирающая открытые обобщения
в закрытые, остаётся отложенной идеей. Текущая закрытая LLVM-сборка не
выполняет такого преобразования исходной программы.

Развивается ppchibicc; независимый проект ppclang в эту работу не входит.
