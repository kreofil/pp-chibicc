# `long double` в LLVM-компиляторе

LLVM-бэкенд ppchibicc поддерживает `long double` для Linux x86-64 с ABI
System V. Используется тип LLVM `x86_fp80`: 64 бита значащей части и 16 бит
знака/порядка. В памяти объект занимает 16 байт с выравниванием 16;
шесть байт padding не относятся к значению.

Это расширенная точность x87, а не `double` и не IEEE binary128. Простая
смена `target triple` не переносит эту реализацию на другую архитектуру.

## Пример

```c
#include <stdio.h>
#include <stdarg.h>

long double precise = 0x1.0000000000000002p0L;

long double sum(int count, ...) {
  va_list ap;
  va_start(ap, count);
  long double result = 0;
  for (int i = 0; i < count; i++)
    result += va_arg(ap, long double);
  va_end(ap);
  return result;
}

int main(void) {
  if (precise - 1.0L != 0x1p-63L || (double)precise != 1.0)
    return 1;
  printf("sum = %.2Lf\n", sum(2, 1.25L, 2.5L));
  return 0;
}
```

Если сохранить пример как `build/long-double-demo.c`:

```sh
bin/ppchibicc --backend=llvm -O2 build/long-double-demo.c \
  -o build/long-double-demo
build/long-double-demo
```

Ожидается `sum = 3.75`. Суффикс `L` сохраняет тип аргументов `...`:
`long double` не продвигается к `double`. Чтение через `va_arg` должно
соответствовать фактически переданному типу. Форматы libc — `%Lf`, `%Le`, `%La`.

## Вычисления и память

Поддерживаются литералы, локальные/глобальные переменные, массивы и поля
структур/объединений, присваивание, арифметика, сравнения, условия,
преобразования между вещественными и целочисленными типами, прямые и
косвенные вызовы. Сохраняются знаковый ноль, NaN, бесконечности и поднормальные
значения; `fast-math` не включается.

Константы IR записываются точно в формате `0xK…`, который понимают LLVM
19, 21 и 23, включая нуль в сравнениях. Глобальная инициализация вычисляется
с сохранением `long double`; промежуточные типы и явные приведения к `float`
или `double` округляют соответствующее значение. Исправлены также
сравнения/условия вещественных констант и преобразования в беззнаковые целые.
Эти исправления общего frontend действуют и в native-бэкенде.

Для self-hosted stage2 исправлены native-преобразования `long double` в
`short`, `unsigned short`, `unsigned int` и `unsigned long`, включая
диапазон от `2^63` до `2^64 - 1`.

## Соглашение вызовов

Скалярный аргумент `long double` передаётся на стеке с выравниванием 16,
результат возвращается в `st(0)`. Он не расходует GP- или SSE-регистры,
учитываемые при передаче последующих структур. Это относится также к
именованным параметрам вариадической функции.

`va_arg(ap, long double)` выравнивает курсор стековой области и читает
16-байтовый аргумент. Поддерживаются чередование с целыми/`double`,
исчерпание регистров, `va_copy`, передача списка другому модулю и libc.
Раскладка `va_list` остаётся общей с предыдущим этапом; подробности — в
[руководстве по вариадическим функциям](llvm-varargs-ru.md).

Классификатор агрегатов учитывает X87/X87UP и их слияние с INTEGER/SSE.
Структура с единственным `long double` передаётся через `byval`, а
возвращается как `x86_fp80`. Объединения с перекрывающимися целочисленными
полями могут использовать INTEGER либо память; крупные/невыровненные
агрегаты используют память и скрытый результат `sret`.

Эти правила ABI агрегатов проверены между LLVM и GCC/Clang. Старый
native-бэкенд пока не реализует все классы X87 для малых агрегатов:
такие структуры между native/LLVM-модулями следует передавать по указателю
либо собирать участвующие функции через LLVM. Для скалярного `long double`
проверены смешанные native/LLVM-модули.

## Функции 4П и проверки

Те же типы поддерживаются в обычных параметрах и результате обработчиков 4П,
включая вариадические обработчики, структуры с полями `long double` и
возврат агрегатов через x87/`sret`. Теги, таблицы и правила диспетчеризации
не меняются.

Готовые примеры из тестов:

```sh
bin/ppchibicc --backend=llvm -O2 test/long-double.c -o build/long-double
build/long-double
bin/ppchibicc --backend=llvm -O2 test/ppc-long-double.c -o build/ppc-long-double
build/ppc-long-double
```

Вывод: `long double OK` и `PPC long double OK` соответственно.

```sh
cmake -S . -B build -DPPCHIBICC_LLVM_VERSION=23
cmake --build build --target test-all test-llvm test-llvm-stage2
```

Общий набор включает native/stage2-проверки констант и преобразований,
IEEE-проверки LLVM, независимый модуль GCC/Clang с вызовами в обе стороны,
проверки регистровых границ, вложенных/packed-агрегатов, вариадических
списков, обработчиков 4П и раздельной компиляции. LLVM-программы проверяются
при `O0`/`O2`, включая публичный режим `--backend=llvm`.

Агрегаты среди безымянных аргументов `...`, агрегатный `va_arg`, а также
остальные ограничения [бэкенда](llvm-backend-ru.md) остаются следующими
направлениями развития.
