# Структуры и объединения среди `...` в LLVM

На Linux x86-64 / System V ppchibicc передаёт агрегаты среди неименованных
аргументов вариадической функции и читает их через `va_arg(ap, Type)`.
Режим включён по умолчанию при `--backend=llvm`, дополнительных ключей нет.
Поддерживаются обычные функции, указатели на функции и обработчики 4П.

```c
#include <stdarg.h>
#include <stdio.h>

typedef struct Item { double value; int weight; } Item;

double total(int count, ...) {
  va_list ap;
  va_start(ap, count);
  double sum = 0;
  for (int i = 0; i < count; ++i) {
    Item item = va_arg(ap, Item);
    sum += item.value * item.weight;
  }
  va_end(ap);
  return sum;
}

int main(void) {
  Item a = {1.5, 2}, b = {2.5, 4};
  printf("total=%.1f\n", total(2, a, b)); // total=13.0
}
```

## Типы и время жизни

Структуры и объединения не проходят скалярные продвижения C. Например,
два поля `float` остаются двумя `float`, даже если скалярный аргумент
`float` среди `...` продвигается к `double`. Тип в `va_arg` должен
соответствовать переданному типу. Сведения о типах во время выполнения
не добавляются; число и порядок аргументов задаёт сама программа.

Допустимы полные объектные типы, поддерживаемые LLVM-бэкендом, включая
вложенные структуры, массивы-поля, объединения, битовые и вещественные
поля. Сам массив, VLA, функция, `void` и неполная структура как тип
результата `va_arg` диагностируются. Проверяется также тип выражения списка.

Результат агрегатного `va_arg` собирается в отдельном временном объекте.
Его можно присвоить, передать функции, вернуть или прочитать поле:
`long x = va_arg(ap, Pair).first;`. Выражение списка вычисляется один раз.
Для каждого выражения выделяется один буфер при входе в функцию; повторение
в цикле не наращивает стек. При передаче аргументов по значению создаются
отдельные снимки, а изменения локальной копии не меняют объект вызывающего.

## Регистры и стек

Используется та же классификация, что для именованных агрегатных параметров.

| Пример | Передача и чтение |
| --- | --- |
| `{ long a, b; }` | До двух GP-регистров |
| `{ double a, b; }` | До двух SSE-регистров |
| `{ long n; double value; }` | Один GP- и один SSE-регистр |
| `{ float a, b; }` | Один SSE-регистр, два значения в его младшей части |
| Крупный либо невыровненный агрегат | Стековая область |
| Агрегат класса X87 с `long double` | Стековая область с выравниванием |

Объединения учитывают все варианты: INTEGER имеет приоритет при слиянии
с SSE. Заполнение структуры не расходует регистры. Регистр для скрытого
`sret` и указатели полиморфных параметров входят в число именованных
аргументов; `va_start` начинает чтение после них.

Для регистра сохраняется шаг 8 байт в GP-области и 16 байт в SSE-области.
Если агрегату не хватает хотя бы одного класса, он целиком передаётся
через память. Ни один курсор регистров при этом не сдвигается: последующий
аргумент другого типа ещё может использовать свободный регистр.

Стековый курсор выравнивается согласно типу, затем продвигается на размер,
округлённый до восьми байт. Проверены выравнивания 16 и 32 байта, упакованные
объекты и поля, пересекающие границы восьмибайтовых частей.

`llvm.va_start` создаёт состояние списка. Чтение агрегата явно понижается
в проверки курсоров, загрузки частей и копирование; универсальная
LLVM-инструкция `va_arg` для этих агрегатов не используется. Полученный IR
можно дальше исследовать и оптимизировать обычными средствами LLVM.

## Копии и взаимодействие модулей

`va_copy` создаёт независимый курсор. Список можно перезапустить через
`va_start` и передать функции-потребителю в другом модуле. Проверены оба
направления GCC/Clang ↔ ppchibicc, в том числе передача самого `va_list`,
обратные вызовы и возврат крупной структуры из вариадической функции.

Представление `va_list` не изменилось: 24 байта состояния, шесть GP-слотов
и восемь 16-байтовых SSE-слотов в 176-байтовой области сохранения.
Правила регистрации обработчиков 4П и формат метаданных v2 сохраняются.

Native-бэкенд также читает обычные GP/SSE-агрегаты. Исправлены подсчёт
регистров для восьмибайтовых структур, использование последнего доступного
регистра и сохранение свободного класса после переноса аргумента на стек.
Для native сохраняются прежние ограничения ABI сложных packed-, X87-,
избыточно выровненных и содержащих заполнение агрегатов. Для полного набора
таких типов используйте LLVM и совместимый GCC/Clang-модуль. После обновления
нужна чистая пересборка native-объектов, передающих агрегаты на границах
регистровых бюджетов.

## Ограничения

Агрегатные аргументы без прототипа по-прежнему диагностируются.
`volatile`, атомарные объекты и остальные ограничения LLVM-бэкенда
также сохраняются; неверный тип в `va_arg` не получает runtime-проверку.

Редкие расхождения ABI GCC и Clang для битовых структур описаны в
[руководстве по битовым полям](llvm-bitfields-ru.md). Они относятся и к
вариадической передаче. Дополнительный пример — структура
`struct { double real; unsigned :3; }`: GCC может расходовать дополнительный
GP-слот при вариадической передаче, тогда как LLVM/Clang используют только
SSE. Для обмена такими типами с GCC передавайте указатель вместо значения.
Обычное хвостовое заполнение без безымянного поля проверено отдельно.

У GCC 13 воспроизведена ошибка оптимизации `va_arg` для объединения
`long double`/INTEGER: выровненная векторная загрузка из GP-области может
падать даже в программе, целиком собранной GCC. Эталонные фикстуры поэтому
проверяют двухрегистровое INTEGER-объединение и X87-агрегат отдельно.
Проверки совмещённого типа прошли с GCC 14 и Clang 23; при взаимодействии
с GCC 13 такой тип безопаснее передавать через указатель.

## Пример 4П и проверки

```sh
cmake -S . -B build
cmake --build build --clean-first -j
bin/ppchibicc --backend=llvm -O2 examples/llvm/ppc-vararg-items.c -o build/ppc-vararg-items
build/ppc-vararg-items
cmake --build build --target test-all test-llvm test-llvm-stage2
cmake --build build --target test-llvm-closed-compiler test-llvm-closed-compiler-stage2
```

Ожидается `normal=13.0 scaled=39.0`: два обработчика принимают одинаковые
значения `Item`, а специализация дополнительно использует свой множитель.

Регрессии включают взаимные вызовы с GCC/Clang, INTEGER/SSE и стек,
нехватку одного класса регистров, `sret`, `va_copy`, однократное вычисление
списка, точные биты NaN/знакового нуля и миллион повторных чтений.
Проверяются все режимы `runtime`, `table`, `switch`, смешанные native/LLVM
модули 4П, закрытая сборка и stage2. Фокусные проверки выполнены на
LLVM 19.1.7, 21.1.8 и 23.1.6 при `O0`/`O2`.
