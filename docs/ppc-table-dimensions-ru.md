# Размеры и индексы таблиц мультиметодов

Размер таблицы функции с несколькими процедурными аргументами равен
произведению числа вариантов каждого аргумента, включая нулевую координату:

```text
slots = extent(T1) × extent(T2) × ... × extent(Tn)
bytes = slots × sizeof(указатель на обработчик)
```

На текущей Linux x86-64 платформе размер указателя равен 8 байтам.
Внутренние произведения и смешанный индекс таблицы теперь вычисляются как
64-битный беззнаковый `unsigned long`. Цикл заполнения таблицы также использует
64-битный счётчик. Числовые признаки специализаций и пользовательские
операции `get_spec_size`, `get_subtype_index`, `get_spec_var_index` сохраняют
свои прежние типы и значения.

## Исправленная ошибка

Ранее произведения вычислялись как 32-битный `int`, а в `unsigned long`
преобразовывался уже готовый результат. Например, 16 аргументов с четырьмя
вариантами дают 2³² ячеек. После переполнения получался ноль: компилятор
генерировал выделение нулевого размера и пропускал заполнение/проверку
полноты таблицы. Ошибка воспроизводилась в обоих backend.

Теперь преобразование к 64-битному типу выполняется до умножений. Отдельно
проверяется возможность представить число байтов таблицы, а не только число
ячеек. Расчёт индекса обработчика тоже не теряет старшие биты.

## Закрытые и открытые типы

Если закрыты все процедурные типы функции, произведение проверяется
компилятором после разбора единицы трансляции. Непредставимая таблица даёт
ошибку с именем функции:

```text
PPC table size overflows for huge
```

Если хотя бы один тип открыт, окончательные размеры берутся из runtime-
метаданных. Конструктор таблицы на приоритете 201 проверяет произведение
перед каждым умножением. Превышение диапазона завершает программу до `main`:

```text
PPC table error: size overflow for huge
```

Представимая таблица выделяется через `calloc`. Его нулевой результат теперь
проверяется до регистрации обработчиков и обхода ячеек:

```text
PPC table error: allocation failed for huge (slots 4294967296)
```

Перед `calloc` гарантируется `slots <= SIZE_MAX / 8`. Нулевой множитель также
отклоняется; корректное обобщение всегда имеет хотя бы нулевой вариант.
Произвольный дополнительный лимит размера runtime-таблиц не вводится.
Возможность выделить представимый объём зависит от системы.

## Совместимость с оптимизацией

Условия оптимизации сохраняются: все процедурные типы должны быть закрыты,
а обработчики — однозначно определены. Предел локального каталога —
16 ячеек, предел статического преобразования по умолчанию — 4096.
Открытые обобщения не становятся закрытыми.

Преобразователь `ppc-static-dispatch.py` учитывает новые диагностические
вызовы в функции выделения таблицы. Они удаляются вместе с её runtime-
поддержкой, когда таблица заменяется константной. Посторонние глобальные
записи и вызовы в удаляемом конструкторе по-прежнему отклоняются.
Метаданные остаются в схеме v2; имена символов, раскладка объектов и
соглашения вызовов не меняются.

После обновления пересоберите PPC-объекты и исходный LLVM IR: старые
артефакты всё ещё содержат прежнюю арифметику и проверки. Компилятор и
поставляемые с ним Python-утилиты следует обновлять вместе.

## Проверки

`test/ppc-table-size.c` проверяет обход матрицы 2×3 через `get_spec_ptr`,
приоритет конкретного обработчика, общий обработчик нулевых координат и
однократное вычисление процедурных аргументов. Тот же исходник имеет
режимы для проверки больших таблиц и отказов выделения памяти.

`cmake/run-ppc-table-size-tests.sh` включает:

- успешную матрицу для открытых и закрытых типов;
- таблицу из 2³² ячеек под ограничением адресного пространства 128 МиБ:
  ожидается ошибка выделения с полным 64-битным числом ячеек;
- детерминированный отказ `calloc` для маленькой таблицы;
- 31 аргумент с четырьмя вариантами: число ячеек представимо, число байтов нет;
- 32 таких аргумента: переполняется также само произведение числа ячеек.

Проверки входят в обычные native stage1/stage2 наборы и в LLVM O0/O2.
Они не пытаются фактически выделить многогигабайтные таблицы. Отрицательные
случаи проверяют точный тип завершения и диагностику до `main`.
Модифицированные для проверки аудита модули сначала проходят `llvm-as`,
затем должны быть отклонены по посторонним действиям в конструкторе.

```sh
cmake --build build --target test-all test-llvm test-llvm-stage2
cmake --build build --target llvm-static-dispatch-demo
```

Для отдельной native-проверки:

```sh
cmake/run-ppc-table-size-tests.sh "$PWD" "$PWD/bin/ppchibicc" \
  "$PWD/build/table-dimensions"
```
