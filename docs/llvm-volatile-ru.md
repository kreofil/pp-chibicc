# Переменные и обращения volatile

В ppchibicc поддерживается квалификатор C `volatile`, в том числе при
`--backend=llvm`. Дополнительная опция для его включения не нужна.
Ключевое слово пишется строчными буквами.

```c
volatile int status;

int sample(volatile int *address) {
  *address = 7;
  int first = *address;
  int second = *address;
  return first + second;
}
```

Вызов `sample(&status)` выполняет запись и два отдельных чтения. Для LLVM
они помечаются `store volatile` и `load volatile`; O2 сохраняет эти
обращения, даже если результат отдельного чтения не используется.
Порядок последовательных volatile-обращений также сохраняется.
Присваивание возвращает записанное значение без дополнительного чтения
результата. `sizeof(status)` и `&status` не читают значение переменной.
Скалярная инициализация не выполняет предварительную запись нуля.
Квалификатор относится к объекту, а не к вычисленному скалярному значению:
например, `typeof(status + 0)` даёт обычный `int`, а `typeof(status)`
сохраняет `volatile`. Операнд `typeof` в этих примерах не вычисляется.

Прямой x86-64 генератор выполняет обычные скалярные чтения/записи без
оптимизатора. Общий frontend сохраняет квалификаторы для обоих бэкендов;
LLVM теперь передаёт их внешнему оптимизатору вместо отказа в компиляции.

## Указатели, массивы и поля

| Объявление | Какие обращения volatile |
| --- | --- |
| `volatile int value` | Чтение и запись `value` |
| `volatile int *p` | Обращение к `*p`; сам указатель обычный |
| `int *volatile p` | Чтение и запись `p`; `*p` имеет обычный тип `int` |
| `volatile int *volatile p` | Обращения к указателю и к указанному значению |

Поддерживаются целые, перечисления, `_Bool`/`bool`, float/double/long double,
локальные и глобальные объекты, параметры и явные приведения указателей.
Свойство доступа определяется типом выражения: приведение к `volatile int *`
создаёт volatile-доступ при разыменовании. Снятие квалификатора приведением
не сохраняет это свойство автоматически.

Для массивов квалификатор относится к элементам. Это работает и с `typedef`
массива, вложенными массивами, локальными VLA и параметрами:

```c
typedef int Matrix[2][3];
volatile Matrix samples;
int last(volatile Matrix values) { return values[1][2]; }
```

Запись `int values[volatile n]` в параметре квалифицирует преобразованный
указатель, а `volatile int values[n]` — его элементы. Указатели на ранее
объявленные структуры и объединения сохраняют квалификатор после появления
полного определения типа.

Поле volatile-структуры/объединения наследует квалификатор, включая
анонимные вложенные структуры и массивы-поля. Можно квалифицировать только
конкретные поля. Квалификация поля-указателя не квалифицирует его адресат.

## Агрегаты, битовые поля и 4П

Копирование структуры/объединения, содержащего volatile-поле либо целиком
квалифицированного как volatile, консервативно помечает копирование всего
объекта как volatile. Это применяется к присваиванию, передаче по значению,
возврату и инициализации; в IR используется volatile-флаг memory intrinsics
либо volatile-доступ к частям агрегата. Поддерживаются агрегаты в `...`
и чтение через `va_arg`. Неиспользуемое значение volatile-агрегата тоже
читается; массив в аналогичном выражении преобразуется в указатель.

Битовые поля читаются и записываются с volatile-признаком. Для сохранения
соседей запись частичного поля читает содержащие его байты. Поэтому составная
операция наподобие `bits.level += n` может включать отдельное чтение значения
и дополнительное чтение для сохранения соседних битов. Вычисляемое основание
поля и адрес скалярного операнда вычисляются один раз.

Ширина операций с битовыми полями и агрегатами определяется реализацией:
сохраняется принятый доступ к занятым байтам и правила копирования.
Они не обещают конкретной аппаратной транзакции заданной ширины; для неё
используйте подходящий скалярный тип и учитывайте целевую платформу.

Обработчики 4П могут работать с volatile-полями и полиморфными параметрами
вида `volatile Device *d`. Квалификатор сохраняется и при чтении признака
объекта для диспетчеризации. Проверяются `runtime`, `table`, `switch`,
мультиметоды и закрытая LLVM-сборка. Закрытие таблицы обработчиков не снимает
volatile-признак с пользовательских чтений и записей.

## Границы и проверка

`volatile` не делает `++` или присваивание атомарными, не создаёт
межпоточной синхронизации и не является общим барьером для обычной памяти.
Атомарные операции и TLS пока остаются отдельными неподдержанными
возможностями LLVM-бэкенда. Целевая платформа — Linux x86-64 / System V.

```sh
cmake -S . -B build -DPPCHIBICC_LLVM_VERSION=23
cmake --build build --target test-all test-llvm test-llvm-stage2 -j2
bin/ppchibicc --backend=llvm -O2 examples/llvm/volatile-sample.c -o build/volatile-sample
build/volatile-sample
```

Пример выводит `volatile sum=14`. `test/volatile.c` проверяется native,
LLVM O0/O2 и независимым системным C-компилятором. `check-volatile-ir.py`
дополнительно проверяет число и порядок скалярных volatile-обращений до/после
O2, отсутствие чтения при получении адреса/sizeof и сохранение копирований.
`test/ppc-volatile.c` покрывает 4П и закрытые режимы.
