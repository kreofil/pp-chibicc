# Измерение закрытой диспетчеризации LLVM

Цель `llvm-static-dispatch-bench` собирает, проверяет и измеряет четыре
представления закрытых мультиметодов. Она продолжает
[исследование статических таблиц](ppc-static-dispatch-ru.md).

## Запуск

Нужны Linux x86-64, Python 3.8+, системный C-компилятор для линковки,
GNU `size`/`nm` и `llvm-as`, `opt`, `llc`, `llvm-link` одной major-версии,
не ниже 19. Clang, профили и compiler-rt здесь не требуются.

```sh
cmake -S . -B build -DPPCHIBICC_LLVM_VERSION=23
cmake --build build --target llvm-static-dispatch-bench
cat build/llvm-static-dispatch-bench/report.md
```

Альтернатива: `make llvm-static-dispatch-bench`. Короткий прогон:

```sh
PPCHIBICC_BENCH_SAMPLES=3 PPCHIBICC_BENCH_SECONDS=0.01 \
  cmake --build build --target llvm-static-dispatch-bench
```

Цели `test-llvm-static-dispatch-bench` и
`test-llvm-static-dispatch-bench-stage2` выполняют только сборку и проверки.
Они включены в LLVM CI без требований к скорости. Измерения запускаются
отдельно от `test-all`.

## Варианты и нагрузки

| Вариант | Исходное представление | Таблица |
| --- | --- | --- |
| `runtime` | `--ppc-dispatch=runtime`, косвенный вызов | Регистрация конструкторами |
| `switch` | Защищённый `switch` с запасным вызовом | Регистрация конструкторами |
| `static-table` | Исходный runtime-вызов | Статический этап из полного IR |
| `static-switch` | Исходный защищённый `switch` | Тот же статический этап |

Все варианты проходят один `default<O2>`, используют CPU `x86-64` и
одинаковые параметры `llc -O=2 -mcpu=x86-64 -relocation-model=pic`.
Промежуточный IR проверяется verifier.

В [исходниках](../examples/llvm/static-dispatch-bench) заданы закрытые матрицы
`2×3` и `2×3×2`. По два конкретных обработчика занимают нулевую и последнюю
координаты; остальные ячейки заполняет общий обработчик. Для каждой размерности:

- `short`: короткая целочисленная формула;
- `work`: шесть шагов смешивания unsigned 64-bit с определённым переполнением;
- `uniform`: равномерный обход координат с последующим перемешиванием;
- `hot90`: около 90% записей в последнюю конкретную комбинацию, затем перемешивание.

Получаются 8 нагрузок. Равномерность координат не означает равные частоты
функций: общий обработчик занимает 4 из 6 либо 10 из 12 ячеек. Сравнивайте
варианты в пределах одной строки; гистограммы сохраняются в `datasets.json`.

Пакет содержит 4096 записей. Данные задаёт 32-битный LCG
`state = 1664525 * state + 1013904223`; перестановку — алгоритм Фишера — Йетса.
Seed данных выводится из общего seed, размерности и распределения. `short` и
`work` получают одинаковые записи при одинаковой размерности/распределении.
Указатели на реальные объекты готовятся заранее; внутри пакета признаки
получаются динамически. Обработчики изменяют счётчики конкретных/общих вызовов.

## Таймер и методика

Исходный LLVM IR обычного `timer.c` входит в полный набор пяти модулей при
статическом преобразовании. Затем кодогенерация разделяется: этот же модуль
таймера снижается один раз, его определения исключаются из ядра. Четыре
программы линкуют **один объект таймера**, без LTO; SHA256 сохраняется.
Четыре пакетные функции имеют `noinline`, а обработчики доступны для встраивания.
Проверяются границы таймера, наличие пакетных вызовов, запрошенные каталоги
и фактическое удаление runtime-функций статического варианта.

Каждый процесс готовит данные и скалярный эталон, выполняет восемь прогревов,
измеряет цикл пакетов через `CLOCK_MONOTONIC`/`CLOCK_PROCESS_CPUTIME_ID`, затем
проверяет сумму и счётчики. Создание процесса, конструкторы, подготовка,
эталон, прогрев, освобождение и печать исключены. `calls` — число логических
исходных диспетчеризаций, включая встроенные обработчики.

Python независимо воспроизводит данные и арифметику. Проверяются все варианты
и нагрузки, 0/1/17/4096 записей, 1/3 пакета и предельные seeds: 256 запусков,
плюс 52 неправильных набора аргументов. Каждый последующий замер также сверяется
с эталоном.

Общий модуль `llvm_bench.py` калибрует одно число пакетов на нагрузку для всех
вариантов, перемешивает порядок и собирает статистику. По умолчанию:
7 повторов × 8 нагрузок × 4 варианта = **224 замера**.

| Переменная | По умолчанию | Значения |
| --- | --- | --- |
| `PPCHIBICC_BENCH_SAMPLES` | `7` | 3..101 |
| `PPCHIBICC_BENCH_SECONDS` | `0.1` | 0.01..1 с, цель калибровки |
| `PPCHIBICC_BENCH_SEED` | `20261111` | 0..2³²−1 |
| `PPCHIBICC_BENCH_CPU` | `auto` | Первый разрешённый CPU, номер либо `none` |

Предел — миллион пакетов. Медленный вариант выполняет столько же работы и
может превышать целевую длительность. Отчёт содержит медиану нс/вызов, MAD,
CPU time и размеры кода. Отношение больше 1 означает ускорение статического
варианта того же представления. MAD не является доверительным интервалом;
ряды с MAD > 10% и замеры с CPU/wall < 0.8 отмечаются.

Сравниваются полные pipeline: статический этап удаляет конструкторы и меняет
видимость обработчиков. Разность времени не изолирует цену одной загрузки
или ветви. Это микробенчмарк с горячими данными; стоимость запуска отдельно
не измеряется, а результаты относятся к машине, LLVM и входам.

## Артефакты

- `report.md`: сводка времени и размера кода;
- `samples.json/tsv`, `summary.tsv`: проверки, калибровка, порядок,
  медиана/MAD/min/max и CPU time;
- `datasets.json`, `data/*.tsv`: seeds, гистограммы, контрольные суммы и записи;
- `code-sizes.tsv`, `kernel-sizes.tsv`: `.text` ядра/программы/каждой пакетной
  функции, данные и размер ELF без strip;
- `metrics.tsv`: статические счётчики IR и точек вызова;
- `build.json`: команды, версии, CPU, исходный commit и признак изменений,
  SHA256 исходников, компилятора и общего таймера;
- каталоги вариантов: полный/выделенный/оптимизированный IR, bitcode,
  pipeline, ассемблер, объекты, тексты функций и manifests закрытия;
- `source/`, `objects/`, `bin/`: снимки исходников, общий таймер и программы.

`dataset_sha256` вычислен по логическим полям little-endian `<IIIQ` без padding;
отдельно сохраняется SHA256 текстового снимка. Таймер возвращает также
проверяемый 64-битный отпечаток порядка записей.
Повторный запуск удаляет старую сводку до проверки настроек. Режим
`--check-only` сохраняет `checks.json`/`check-info.json`, без отчёта о скорости.

измеряемого цикла. Это наблюдение относится к указанной сборке и данным.
